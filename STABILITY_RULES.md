# Serron — Stability Rules

## 🛡️ Правила стабильности проекта

### 1. Любая правка в app-unified.js
**Правило:** Сначала тест Tabs
- Tabs должны работать ДО и ПОСЛЕ правки
- Если Tabs сломались → откатить правку

### 2. Любая правка скриптов в index.html
**Правило:** Сначала проверка консоли на SyntaxError
- Запустить `node --check` на изменённые файлы
- Проверить браузерную консоль на красные ошибки
- Если есть SyntaxError → исправить ДО коммита

### 3. Ни один модуль не имеет права ломать всё приложение
**Правило:** Все init функции в try/catch
- Используется `safeInit()` для всех модулей
- Ошибка модуля → лог в консоль, остальное работает
- Tabs инициализируются ПЕРВЫМИ и независимо

### 4. Новые фичи добавляются только через отдельный init + try/catch guard
**Правило:** 
- Новая фича → отдельная функция `initFeatureName()`
- Добавить в массив `initModules` с `safeInit()`
- Никогда не добавлять код напрямую в основной поток

### 5. Tabs — критический модуль
**Правило:** Tabs работают независимо от всего
- Tabs инициализируются ПЕРВЫМИ
- Tabs не зависят от Calendar, Profile, Chat
- Если Tabs сломались → это критический баг

### 6. Calendar — изолированный модуль
**Правило:** Calendar не влияет на Tabs
- Calendar инициализируется через `safeInit()`
- Calendar не создаёт глобальных обработчиков, блокирующих Tabs
- Calendar можно отключить без влияния на Tabs

### 7. Pre-commit проверка
**Правило:** Запускать `scripts/check-syntax.js` перед коммитом
- Проверяет синтаксис всех JS файлов
- Если есть ошибки → коммит запрещён

### 8. Runtime guard
**Правило:** Все модули в try/catch
- Используется `safeInit()` wrapper
- Ошибки логируются, но не убивают приложение
- В консоли видно, что запустилось, а что нет

---

## ✅ Чеклист перед коммитом

- [ ] Запущен `node --check` на изменённые файлы
- [ ] Проверена браузерная консоль (нет SyntaxError)
- [ ] Tabs работают (Feed ↔ Talk переключается)
- [ ] Calendar (если включён) открывается
- [ ] Chat input работает
- [ ] F5 перезагрузка не ломает ничего

---

## 🚨 Критические инварианты

1. **Tabs всегда работают** — даже если всё остальное сломано
2. **Нет SyntaxError** — приложение должно загружаться без красных ошибок
3. **Модули изолированы** — ошибка одного модуля не убивает остальные
4. **Init последовательность** — Tabs → Calendar → остальные модули

---

## 📝 Примеры правильного кода

### ✅ Правильно:
```javascript
// Изолированная init функция
function initMyFeature() {
  try {
    // код фичи
    return { success: true };
  } catch (error) {
    console.error('[MYFEATURE] Error:', error);
    return { success: false, error: error.message };
  }
}

// Добавить в initModules
safeInit('MyFeature', initMyFeature);
```

### ❌ Неправильно:
```javascript
// Прямой код без try/catch
window.myFeature = new MyFeature(); // Может упасть и убить всё
```
